# Stabilization release 0.12.0

## What

On 2026-10-07 the maintainer explicitly authorized closing **0.12.0** for
pre-1.0 stabilization, after #126's retained scope and adoption-pause decision.
This authorizes preparation, exact-candidate qualification and publication if
all applicable gates pass. It is a delivery of completed development, not a
new feature cycle or the deferred general public 1.x commitment.

Deliver accepted bounded recorder evidence/collection/requested reporting
(#114), standalone `validate_provider` and its author example (#111–#113/#125),
faithful citation keys (#109), deferred feature imports (#116), editor/name and
CFF book-kind fidelity (#120), and supported DOI presentation (#121).
Retain earlier portable/provider public promises and schemas. The newly
accepted evidence/validator forward promises begin at verified public 0.12.0,
not from its preparation or from the immutable original public 0.11.0.

## How

Use the existing staged noarch route and pinned shared tools. Commit reviewed
version/route inputs, matching root/packaged self-citation and candidate notes.
Bind the final original producer SHA before source gates and archive creation.
Execute ordinary CI, all eight full Linux/macOS arm64 × Python 3.11–3.14 source
matrix cells, both policies, all eight full exact-file installed cells and all
eight real PyUnitWizard receiving cells plus independent aggregation. Retain
the original released 0.9.0 fallback and original detached results.

Against the same archive in an isolated installation, execute the dependency-free
author example, standalone validator/empty-role path and bounded publication
routes from #120–#123: classic BibTeX/Pandoc, both BibLaTeX/Biber styles and
JabRef 5.15 fresh import/reopen. Preserve warnings, original input/output hashes,
no-new-credit behavior and before/after installed identity. Missing designated
engines cannot qualify that route. Historical receipts remain unchanged.

Promote only the inspected and tested original archive SHA-256. Independently
verify public labels/solver index and a clean public Linux/Python 3.14 install
with matching runtime/distribution/self-citation, resources, CLI, detached
provider/evidence/validator behavior, optional absence and dependency closure.
Register the immutable canonical tag at the original producer after public
verification, retain the public receipt, close this issue and hand off actual
version/file/digest/guide identities to the existing owners.

## Why

Consumers need an installable pre-1.0 version containing the improvements already
reviewed in development. New features pause; owning consumers can then adopt
the delivered package and supply habitual-use feedback without requiring
unpublished APIs from public 0.11.0. Source/controlled receiving qualification,
habitual dogfooding, guide synchronization and client releases remain separate.

## Scope and exclusions

the same four runtime dependency floors and original schemas. No new runtime
feature, dependency increase, broad instrumentation, unrelated optimization,
acknowledgements, dashboard or sibling-copy repair. General 1.0, client/platform
decisions and later feedback remain separately owned. GitHub Release/Zenodo
claims require their own observed outcomes; tag/Conda delivery alone proves no
archival. Resume the accepted feature-development pause after delivery.
