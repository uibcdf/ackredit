# Published diagnostic providers

## What

The SMonitor/ArgDigest capabilities previously measured with development wheels
are now public. Provider publication does not by itself establish Ackredit's
receiving behavior. This extends #115/#118 without changing their identities.

## How

Install original public Ackredit 0.11.0, SMonitor 0.19.0 build 1 and ArgDigest
0.15.0 build 0 with strict ordinary channels. Reuse shared public verification,
installed smoke and lifecycle tools. Separately normally install the unchanged
Ackredit runtime candidate and execute scoped diagnostic/registration guards and
applicable existing contracts with the public providers and pytest-receptor.

## Why

Verify application-policy preservation, active argument validation, native
failure identity and independent attribution under explicit metadata-only
scopes. Keep actual published closure separate from source/provider proposals.

## What was refuted

New provider availability alone does not justify raising Ackredit's dependency
floors, selecting pipeline-only argument execution or changing diagnostic defaults.

## Scope and exclusions

One Linux/Python 3.14 receiving lane; no new Ackredit release, provider source
edits, synchronized-guide repair or wider-platform/scientific equivalence claim.
Shared coordination remains uibcdf/molsyssuite#106.

## Acceptance criteria

Verified original public identities, normal installed receiving evidence,
focused guards, maintained current guidance, preserved historical receipts,
applicable local gates and inspected exact-head CI. Hand back consumer evidence
to the existing coordination issue and archive this bounded report.
